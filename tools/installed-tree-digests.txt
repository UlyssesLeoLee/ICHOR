# Recorded digests of the installed dependency tree (apps/studio/node_modules)
#
# Produced by `node tools/tree_digest.mjs <tree-root>` — see that tool's
# file header for the exact recipe. The digest is PATH-INDEPENDENT (only
# paths relative to the tree root take part), so the same checkout
# installed on different machines gives the same value.
#
# It is PLATFORM-DEPENDENT, and that is a property of the lockfile, not of
# the recipe: apps/studio/package-lock.json declares 40 platform-specific
# optional entries (@next/swc-<platform>, @img/sharp-<platform>,
# @img/sharp-libvips-*). npm only installs the ones matching the host
# platform, so a Windows install and a Linux install legitimately produce
# different trees. The values are therefore recorded per platform, and
# `--check` compares against the entry for the platform it runs on.
#
# It is also NPM-VERSION-DEPENDENT. npm 10.9.9 and npm 12.2.0 resolve the
# SAME lockfile to different trees: npm 12 no longer installs
# @emnapi/runtime and @img/sharp-wasm32. The win32-x64 values below were
# measured under both npm versions, from the same committed lockfile; see
# docs/evidence/ATS-102/14-npm-version-and-install-digest.log. The build gate
# asserts the npm version in its `checknode` step, so a mismatch points at
# the npm version rather than at the lockfiles.
#
# Format:  <scope> <platform> <npm-version> <sha256>
#   scope       all-files | package-json
#   platform    <process.platform>-<process.arch>
#   npm-version the npm that produced the value
#
# To re-measure after an intentional dependency change:
#   npm ci --prefix apps/studio && node tools/tree_digest.mjs apps/studio/node_modules
#   node tools/tree_digest.mjs apps/studio/node_modules --package-json-only
