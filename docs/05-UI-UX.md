# ATS-UI-001 画面設計書 / UX 规范

## 1. 导航与界面模型

采用低认知负荷的单工作台：左侧固定一级导航，顶部项目切换及 Git 状态，二级左栏为资源列表，右侧为当前上下文详情；执行信息不强制打开另一个应用。视觉主题为深蓝中性色配有限强调色（蓝色交互/绿色通过/红色失败）；避免复杂纹理、无意义动画和多余仪表盘卡片。

## 2. 一致性和异常反馈

- 导入：必须填本地绝对路径；失败显示缺失 `package.json` 或 `playwright.config`，不自动生成项目。
- 代码编辑：保存按钮只有草稿变化时可点击；基线 Hash 变化时禁止覆盖并提示重新加载；文件默认仍受 Git 版本管理。
- 运行：每个项目仅允许一个正在运行的 Run；运行时显示日志轮询；停止为可请求，最终状态以进程关闭为准。
- 结果：Passed、Failed、Error、Interrupted、Cancelled 不可混为一谈；报告文件独立下载，不嵌入未清理的测试 HTML。
- 质量概览（ATS-216）：取消（Cancelled）与失败（Failed）分桶，取消既不计入失败也不计入通过率，取消运行的用例也不进判定类指标；重试后通过（Flaky）单列，既不算通过也不算失败，初次尝试的失败与其错误仍可见；每个指标与原始结果逐项对账（对账同时核对界面显示的数与 Bridge 报告的计数器），不一致时列出差异而非抹平；界面提供「原始结果」面板，每个显示出来的数字可展开到它计数所依据的用例或运行。
- 证据工作台（ATS-215）：失败用例与其 Trace 在同一屏，点击预算 2 次是数出来的（模块返回点击路径，界面显示这个数）；定位不到 Trace 时显示原因而不是给一条打不开的链接；附件显示的是**归档时**清单记录的 SHA-256（ATS-209）与文件自身的修改时间，不是现在重算的摘要——归档后被改动的文件仍显示归档值，并由校验结果另行报出 changed/missing，两者不互相冒充；Trace Viewer 是引擎附带的独立程序，界面给出产生该 trace 的引擎版本，但**不代为打开 trace**。
- 需求追踪：未配置 `.aitest` 文件时呈现空状态/示例，不伪造覆盖率。
- 工作台四态（ATS-111）：**空列表 / 加载失败 / 已取消 / 加载中**四种状态在界面上必须互相可辨，不得都落成「什么都没有」或同一个 spinner。四态由一份模型定义（`apps/studio/lib/workbench-state.mjs`），界面只渲染模型说的东西，因此两个界面不会各说各话：
  - 空列表「暂无内容」：请求成功且该项目确实没有用例；与「筛选条件没匹配上」是**两件事**，后者单独提示，不冒充空列表。
  - 加载失败「加载失败」：`role="alert"`、`aria-live="assertive"`，失败会打断读者；文案带上原因，并给出「重试」入口与「检查本地执行服务是否在运行」的下一步。
  - 已取消「已取消」：**取消既不是失败也不是空**。目录加载走 `apps/studio/lib/api.ts` 的 `cancellableApi`（AbortController），切换项目时旧请求被中止；读者按 Esc 可取消正在进行的加载，面板随即显示「已取消」。
  - 加载中「加载中」：`aria-busy="true"`，并提示「按 Esc 可以取消这次加载」。
  - 状态**不只以颜色区分**（§4）：四态各有独立的图标、标签、说明与「接下来可以做什么」提示；四个标签是四个不同的词。
  - 模型不认识的 outcome 一律报成**失败**，不报成「暂无内容」——把未知说成成功就是撒谎。
  - 「重新加载」必须**真的重新发出请求**：失败、已取消、空三态都提供该入口，点击后请求数增加、面板回到「加载中」。把项目重设为同一个值不是状态变化，React 不会重跑加载副作用，所以入口背后是一个递增的重载计数。
  - **切换项目时清空上一项目的目录**：加载中、已取消、加载失败的面板下不得残留上一个项目的用例，「可管理用例」指标与页脚计数同样归零——把别的项目的用例当作当前项目展示，是把事实说错。
  - **没有项目时**给出工作区级空状态「尚未选择项目」，含导入项目的引导；它不属于四态（不是某次请求的结果），也不能退化成「筛选没匹配上」。
- 键盘（ATS-111）：核心流程可**纯键盘**走完，不是「有 tabindex」：
  - 首个 Tab 落在「跳到主要内容」跳转链接上；焦点环**可见**（基准样式表在项目下拉、搜索框、弹窗输入框三处写了 `outline:none`，本项为这三处补回可见焦点环）；
  - 焦点顺序与 DOM 一致（rail → refresh → project-select → add-project → search → sidebar → panel → content）；refresh 在顶栏，故先于项目下拉；该顺序由 ST 探针在真实浏览器中**按顺序逐项比对**（不是把观测序列与自身比较），并用一条打乱顺序的反例证明该比对会失败；
  - `Esc` 取消（弹窗优先，其次取消正在进行的加载，再其次停掉正在进行的运行）、`Enter` 提交（添加项目弹窗是真正的 form，走浏览器原生提交）、`Ctrl+Enter` 运行当前用例、`Ctrl+P` 跳到脚本搜索框；
  - 快捷键绑定在 **document** 上，而非某个容器：焦点落在 `<body>`（首次加载、弹窗关闭后）时，`Esc` 与 `Ctrl+P` 依然生效；弹窗关闭后焦点**归还**给「添加项目」按钮。
  - `Esc` 的目标是**嵌套的**，由模型 `escapeTarget()` 决定：**弹窗 → 加载 → 运行**，最内层优先；三者都没有进行中时 `Esc` 不做任何事。
  - **`Esc` 能停掉正在进行的运行**：与「停止运行」按钮走同一个 `POST /api/runs/<id>/stop` 接口，运行的终态由引擎退出决定（取消记为「已取消」，不记为「失败」）。页脚快捷键清单写的是「关闭弹窗，或取消正在进行的加载或运行」——**写下来的就必须做得到**，做不到就不能写。
  - **弹窗打开时 `Ctrl+P` 必须被消费**（`preventDefault()`）：焦点留在弹窗内，按键**不漏给浏览器**的打印命令。弹窗是模态的，模态对话框吞掉自己的快捷键是它「独占」承诺的一部分。
  - `Enter` **不得吞掉焦点控件自己的动作**：焦点在按钮、链接或 summary 上时由浏览器触发其原生 click，所以对「取消」按 Enter 是**取消**，不会把项目注册进去。
  - 文本框里的 `Enter` 留给浏览器（`isTextEntry` 守卫），打字时不会被工作台抢走；输入法的组词过程中（`isComposing`）按键属于输入法，不触发工作台命令。
  - 弹窗声明 `aria-modal="true"` 就必须**真的**约束焦点：Tab 在弹窗内循环，不会跑到背景里。
  - 快捷键清单写在页脚「键盘操作」里：**不写下来的快捷键等于没有快捷键**；**写下来却做不到的快捷键等于谎报**。
- Agent：所有建议必须标识 Evidence source、model、工具权限、风险级别和审核人（P1）。

## 3. 三视图同步约束

脚本是唯一权威文本。Graph 是只读语义投影：可显示不意味着支持反向修改；不能解析的结构显示 CodeBlock/未支持提醒。代码视图进行保存时触发索引刷新，不转换任意闭包。历史执行的证据不随代码变更重算，应保留运行当时的 commit 与文件哈希（后者 P1）。

## 4. 键盘、可用性、响应式

P0：按钮有文字或 title、Tab 可进入输入框、列表按当前项目过滤、文字对比度高、状态不能仅以颜色区分。宽屏 3 栏；窄屏压缩次要元素。P1：快捷键 `Ctrl+P` 脚本搜索、`Ctrl+Enter` 运行当前用例、Graph 画布缩放、可聚焦节点和 aria-label、对屏幕阅读器更友好。

### 4.1 已实现（ATS-111，Next 工作台）

P0 与 P1 中的键盘项已在 Next 工作台实现并实测（真实 Chromium，`tools/ats111-probes/st-ats111.mjs`）：

- 四态可辨识（见 §2），状态不依赖颜色；
- 焦点可见（补回被基准样式表去掉的 `outline:none`）、焦点顺序与 DOM 一致、跳转链接为首个可聚焦元素；
- `Esc` 取消、`Enter` 提交、`Ctrl+Enter` 运行、`Ctrl+P` 搜索，快捷键清单在页脚可见。

这些结论各自都有**可证伪**的检查，而不是只跑通即算数：

- 焦点顺序的比对**按顺序逐项进行**，并配一条打乱顺序的反例证明该比对会失败；
- 「重新加载」在失败 / 已取消 / 空三态下都实测请求数增加（不是把状态设成它本来的值）；
- 切换项目时实测面板、指标、页脚都不残留上一个项目的用例；
- 没有项目时实测面板给出「尚未选择项目」与导入引导（断言的是**渲染出了 state panel**，不是「不出现某串文字」）；
- 对焦点控件按 `Enter` 实测走控件自己的动作（对「取消」按 Enter 是取消，项目未被注册；此处输入的路径**从未注册过**，所以误提交必然被计数发现）；
- 焦点在 `<body>` 时实测 `Esc` 与 `Ctrl+P` 依然生效，弹窗关闭后焦点回到「添加项目」按钮；
- **`Esc` 停掉正在进行的运行**：实测运行的终态从 `running` 变为「已取消」，且按键在 window 层被观测为 `defaultPrevented=true`；
- **弹窗打开时 `Ctrl+P` 被消费**：实测按键 `defaultPrevented=true` 且焦点仍在弹窗内；
- 变异探针（`tools/ats111-probes/mutation-check.mjs`）对**模型**与**视图接线**各做一组变异，每个变异都必须让对应的测试变红——视图侧的变异（重载空转、`Enter` 吞按钮、切换不清目录、快捷键绑在容器上、`Esc` 不停运行、弹窗内 `Ctrl+P` 不被消费、轮询失败被吞掉、取消绕过焦点归还）正是历轮复核发现的缺陷类型。

**「修复前必须失败」的可证伪性**：同一套视图级检查在**两次被驳回的交付**上跑出红项——基线 A（`cb742ca`，第 1 次交付）得到 `04b-prefix-system-test-A.log`（55/79，绑定的 11 条检查全部 FAIL），基线 B（`9e305e7`，第 2 次交付）得到 `04b-prefix-system-test-B.log`（72/79，绑定的 3 条检查全部 FAIL）。**两个基线各自绑定一组检查**，而不是一棵树跑出一堆红项：第 2 轮的两条缺陷（`Esc` 不停运行、弹窗内 `Ctrl+P` 不被消费）只存在于第 2 次交付上，单基线会让「本该通过」与「不具区分度」分不开。该检查比对的是**具体检查项的编号**，不是「有检查失败了」——无关的失败不算通过。**「修复前」的那棵树是钉死的提交号**（`tools/ats111-probes/lib/pre-fix-commit.sh`），不是 `git log --grep` 搜索：搜索会随着后续合并往前漂，漂到修复后的树上就会把「检查不具区分度」的结论错误地套在一棵没坏的树上。

**已知边界**：本项只覆盖 Next 工作台（`apps/studio/app/page.tsx`），零依赖便携 UI（`apps/studio/public/fallback.html`）**未**同步这四态与键盘模型；屏幕阅读器（NVDA/JAWS/VoiceOver）**未**实机验证——本项断言的是 ARIA 语义与 live region 的正确性，不等于屏幕阅读器实测；焦点环按 WCAG 2.2 的 `:focus-visible` 语义实现，未做对比度实测；焦点陷阱与 `aria-modal` 的一致性在真实 Chromium 中实测，屏幕阅读器如何播报未实测；键盘导航覆盖的是主流程（选择项目→搜索→打开用例→运行→查看运行），表格内逐单元格键盘导航与虚拟滚动的键盘操作未覆盖；运行列表轮询失败时，Next 工作台的旧运行行**已**标注为「已过期」（行带 `data-stale="true"`，面板带 `data-region="runs-stale"` 的说明，由 `ST-111-19a~e` 五条检查守住，轮询恢复后标注消失）；**未**同步这四态与键盘模型的**零依赖便携 UI**（`apps/studio/public/fallback.html`）的运行列表没有这一标注——本项的四态与键盘模型只覆盖 Next 工作台。

## 5. 版本差异

正式 Next 页面为桌面原型主 UI，使用 Monaco；便携 HTML 为离线验证入口，内嵌 textarea 代码编辑但操作真实 API。二者均不使用演示用假 Run 数据。Next 构建和 Tauri 原生环境尚未实机验证，必须遵循 ST 文档测试。
