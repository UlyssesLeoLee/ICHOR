## 1. 本任务要解决什么

ATS-214 的验收标准是四句话（issue 描述）：

| # | 验收句 | 本设计书的落点 |
|---|---|---|
| 1 | 「能按用例名 / 文件 / 标签检索，检索结果与用例清单一致」 | §3 搜索口径、§4 标签口径 |
| 2 | 「能按标签过滤，标签口径要写清（多标签是「任一」还是「全部」）」 | §4 标签口径 |
| 3 | 「过滤条件与搜索条件叠加时，结果必须符合集合语义」 | §5 集合语义 |
| 4 | 「选中多个用例后能发起批量运行；选择集合要能被复现」 | §6 选择集合、§7 批量运行 |

三条半是**语义**要求而不是代码要求：读者必须能预测列表会显示什么。因此语义只有一处实现
（§2），两个界面都导入它。

## 2. 一份实现，两个界面

仓库里有两个用户界面：

- Next.js 工作台 `apps/studio/app/page.tsx`
- 零依赖便携 UI `apps/studio/public/fallback.html`

Bridge 从 `apps/studio/out` 与 `apps/studio/public` 提供静态文件
（`server/index.mjs` → `staticFile()`），因此放在 `public/` 下的模块可被便携 UI 以稳定
URL 访问。把实现放在那里，两个界面导入的是**同一份代码**，口径不可能各说各话。

本任务沿用仓库既有的做法（`quality.mjs` / ATS-216、`evidence-workbench.mjs` / ATS-215）：

| 文件 | 作用 |
|---|---|
| `apps/studio/public/case-search.mjs` | 搜索 / 标签 / 过滤 / 选择集合的**唯一**实现 |
| `apps/studio/app/page.tsx` | Next 工作台：只提供输入，语义在共享模块 |
| `apps/studio/public/fallback.html` | 便携 UI：同上 |
| `server/uid.mjs` | 静态索引读标签（`scanCaseTags`） |
| `server/core.mjs` | 标签进入目录（静态 + 权威 + 移动端） |
| `server/index.mjs` | 运行请求的 `selection` 字段、批次链 |

共享模块是**纯 ECMAScript Module + JSDoc 类型**：Next 应用（TypeScript 读 JSDoc）、
Node 测试运行器（`node --test`）、浏览器（ES module）都能导入，不需要自己的构建步骤。

## 3. 搜索口径

搜索在**三个字段**上进行，用**同一条规则**：大小写不敏感的子串匹配。

| 字段 | 例 | 说明 |
|---|---|---|
| 用例名 | `登录` | 命中 `用户登录`、`登录失败提示`，不命中 `登出` |
| 文件 | `cart.spec` | 命中 `tests/cart.spec.ts` 下的全部用例 |
| 标签 | `smoke` | 命中带 `smoke` 标签的用例（作者写 `@smoke`，引擎报 `smoke`） |

三条字段**一起搜**而不是分成三个条件：输入 `smoke` 的用户是在找带 smoke 标签的用例，
不管它在哪个文件；输入文件名的用户要的是那个文件里的用例。

**空查询不是过滤条件**：空搜索框保留全部用例。若把空查询当成「什么都不匹配」，
目录在用户打字之前就是空的。

**结果是清单的子集**：`filterCases()` 返回的是传入用例对象本身（保序），不会出现清单里
没有的用例（UT-ATS214-006 对多个查询断言了这一点）。

## 4. 标签口径

### 4.1 标签从哪来（实测）

Playwright 的 `--list` JSON **带标签**（`spec.tags`）。本机实测（真实 Playwright 1.64.1）：

| 源码 | CLI 报告 |
|---|---|
| `test('x', { tag: '@smoke' }, ...)` | `['smoke']` |
| `test('x', { tag: ['@a', '@b'] }, ...)` | `['a', 'b']` |
| `describe('g', { tag: '@group' }, ...)` 内的用例 | `['group', ...用例自己的标签]` |
| 嵌套 describe | 外层 + 内层 + 用例自己的，逐层累加 |
| 重复标签 | `['a', 'a']`（引擎不去重） |

两条必须记住的事实：

1. **CLI 要求标签以 `@` 开头**（否则整个文件被拒：`Error: Tag must start with '@'`），
   但**报告时不含 `@`**。所以比较标签时两边都去掉前导 `@`。
2. **describe 的标签被其内的用例继承**，逐层累加。

### 4.2 两个索引的标签必须一致

- **权威索引**：标签直接来自 CLI（`server/discovery/playwright-list.mjs` 解析 `spec.tags`）。
- **静态索引**：标签由本任务新增的词法读取器读出（`server/uid.mjs` 的 `scanCaseTags`），
  读 details 对象的 `tag`/`tags` 属性，并继承 describe 的标签。

如果静态索引不读标签，标签过滤就会在**可信项目上能用、未可信项目上永远匹配不到**——
这读起来像「过滤器坏了」，而不是「过滤器没看到标签」。所以静态索引也读。

**实测**：同一份夹具，静态索引与真实 CLI 的 `--list` 输出**逐条一致**（6 条用例，标签全同）
——见 `docs/evidence/ATS-214/03-tag-parity.log`。

### 4.3 不读计算式标签

`{ tag: someVar }` 不读。静态索引不求值代码，猜出来的标签会让过滤结果错配——
一个猜错的标签比一个缺失的标签更糟。

### 4.4 多标签的口径

勾选多个标签有两种可能的口径，一个不说清楚自己用哪种的界面就是在隐瞒：

| 口径 | 含义 | 集合运算 |
|---|---|---|
| `any`（任一） | 用例**至少**带一个被选中的标签 | 并集 |
| `all`（全部） | 用例**带全**被选中的标签 | 交集 |

**本任务默认 `any`（任一）**：标签过滤是「把标了这类的东西给我看」的功能，
读者勾两个标签时期待的是并集。`all` 也实现了，界面用「任一 / 全部」下拉标注当前口径。

两个口径**必须真的不同**（UT-ATS214-011 断言 `any` 4 条、`all` 2 条，且 `all ⊆ any`）。
若两者实现相同，「口径」就只是个装饰。

### 4.5 标签比较

- **大小写不敏感**：标签是标签，`Smoke` 与 `smoke` 对人是同一个标签。
- **忽略前导 `@`**：用户输入 `@smoke` 必须能找到引擎报告的 `smoke`。
- 列表**去重且有序**。

## 5. 集合语义（最容易做错的一条）

四个条件各自是一个**集合**，结果是它们的**交集**：

```
result = search ∩ tag ∩ file ∩ status
```

**不是并集**，也**不是「后一个条件替换前一个」**。

两种错误都是**静默**的——列表看起来仍然合理：

- **并集**：勾一个标签把列表**变宽**。UT-ATS214-016 用一个 2 条与 3 条的条件断言结果是 2 条
  而不是 3 条；UT-ATS214-017 用两个**互不相交**的条件断言交集为空，而并集会是 3 条。
- **替换**：清掉标签条件把搜索条件一起清掉。UT-ATS214-018 双向断言：清掉标签后搜索仍在，
  清掉搜索后标签仍在。

**每个条件各保留了多少条单独报出来**（`describeFilter()`）：因此「没有匹配」与
「交集为空」是可区分的——读者能看到搜索保留了 2 条、标签保留了 1 条，而交集是 0 条。
单看列表分不出这两件事。

筛选后的**顺序是目录的顺序**：列表是目录的一个视图，不是重新排序的结果，所以筛选不会
改变用户看到的顺序。

## 6. 选择集合

### 6.1 它是一个集合

选择是**用例 UID 的集合**：勾选的顺序不是它的一部分，两次相同的勾选产生完全相同的快照
（UT-ATS214-025 / UT-ATS214-028）。

### 6.2 快照是自含的

`selectionSnapshot()` 产出的记录带每条用例的**文件、标题、行号**：

```
{ uids: [...], cases: [{uid, file, title, line}, ...], count, unknown }
```

自含的理由：目录每次轮询都会重读，用例可能已被改名、移动或删除。只记 UID 的记录，
过一会儿就变成一份没人读得懂的标识符列表。

### 6.3 目录不认识的 UID 被**报告**，不被静默丢弃

`unknown` 列出目录里没有的 UID（UT-ATS214-027）。调用方据此**拒绝**整个选择：
静默跳过会得到一次覆盖更少用例的运行，而运行记录却会说自己覆盖了全部——
选择就成了主张而不是记录。

### 6.4 按文件分组

引擎每次只接受**一个**测试文件过滤参数（ATS-106 的参数基线拒绝第二个位置参数），
因此跨文件的批量运行必须按文件拆开。分组是选择语义的一部分，界面上先显示
「将分 N 个文件依次执行」，再让用户按下按钮。

## 7. 批量运行

### 7.1 请求

`POST /api/projects/:id/run` 新增**一个**可选字段 `selection`（用例 UID 数组）。
ATS-106 的白名单机制保持不变：`file` / `capabilities` / `runner` / `env` / `selection`
之外的任何字段仍以 `400 RUN_PARAMETER_NOT_ALLOWED` 拒绝。

| 情况 | 响应 |
|---|---|
| `selection` 不是数组 | `400 SELECTION_NOT_AN_ARRAY` |
| `selection` 是空数组 | `400 SELECTION_EMPTY` |
| 有 UID 不在目录里 | `400 SELECTION_UNKNOWN_CASE`（附 `unknown` 数组） |
| 正常 | `202`，运行记录带 `selection` 与 `selectionUids` |

**有选择时 `file` 由选择决定**（第一个分组的文件）：调用方同时送 `file` 和 `selection`
会有两个事实来源，而它们可以互相矛盾。

### 7.2 批次链

选择跨多个文件时，它是一个**批次**：每个文件一次运行，前一个到达终态后启动下一个。

链在**运行结束时**推进（`advanceBatch()`），而不是靠定时器或轮询：下一个运行不能在前一个
还持有项目时启动（Bridge 拒绝同项目第二个运行），而「运行结束」正是前一个已确定释放项目
的那一刻。定时器只能**猜**项目什么时候空出来。

被**取消**的运行会终止链：用户要求停止，继续跑下一个文件等于跑用户已经不要的用例。

批次记录（`batchUid` / `groups` / `runs`）说明选择被怎样拆分、每个文件做了什么。

### 7.3 「选了什么、跑了什么」可复现

运行记录里的**选择集合**与本次运行的 **attempt** 是两条**独立**的事实：

- 选择集合：运行开始时的快照（哪些用例、各自的文件/标题/行号）
- attempt：引擎实际跑出来的、绑定了 UID 的执行记录

界面的对账表逐项列出：

| 核对项 | 含义 |
|---|---|
| 选中用例 | 运行记录里的选择集合 |
| 实际执行的用例 | 本次运行的 attempt 绑定的 UID |
| 选中但未执行 | 缺失——引擎没跑，或身份映射器绑不上 |
| 执行但未选中 | 多跑——引擎按文件跑，会跑该文件里的其它用例 |
| 选择可复现 | 选中的用例是否全部执行 |

**多跑不破坏「可复现」**：选择集合仍然就是用户选中的那几条。但它必须被看见——
「我选了 3 条，跑了 5 条」是读者需要知道的事实。

## 8. 已知边界

1. **没有「按 UID 精确执行单个用例」**。适配器的 `filterByTestUid` 能力仍为 `false`
   （ATS-301 登记的既有缺口），所以跨文件批量运行时引擎会跑该文件内的**全部**用例；
   多跑的用例由对账表报出。实现这一条需要改适配器契约与运行参数基线，超出本任务范围。
2. **标签只认 details 对象里的字面量**。经变量、函数或配置计算出来的标签读不到
   （静态索引不求值代码）。
3. **便携 UI 的批量运行按钮未实现**。其检索、过滤与标签口径由同一模块保证一致，
   但零依赖约束下只做检索与过滤。
4. **状态过滤在本任务里没有数据源**：用例在跑过之前没有状态。共享模块提供了
   `statusOf` 回调入口与该条件，但没有界面使用它。
5. **人工可用性（无障碍 / 键盘 / 加载态）未评测**，属 ATS-111。
6. 只在 Windows 11 + Node 上实测，未在 macOS / Linux 上跑过。
