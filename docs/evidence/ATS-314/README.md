## 1. 每一份日志是什么

每一份日志都是**命令的输出**，不是命令的描述。每一份日志的头部都写明
**它描述的是哪一棵树**（commit / node / platform / 命令），因为一个没有
树的数字是没有意义的数字，而没有树的数字在别的票一碰这棵树时就会过期
——ATS-308 的第一次采集就是这样翻车的。

| 日志 | 内容 | 判定 |
|---|---|---|
| `01-node-test-ast-subset-ut.log` | 单元测试（白名单、静态规则、理由码、文件三态） | `ℹ tests 48 / pass 48 / fail 0` |
| `02-node-test-ast-subset-it.log` | 集成测试（**实 Bridge** 上的 HTTP 面：判定到达了用户面前） | `ℹ tests 10 / pass 10 / fail 0` |
| `03-probe-ast-subset.log` | 真实脚本上的实测（`examples/` 的 5 个 Playwright/WDIO 脚本） | `RESULT: OK` |
| `04-node-test-negative-control.log` | **负向对照**：8 种变异逐条被抓住 | `ℹ tests 8 / pass 8 / fail 0` |
| `05-ats301-gate.log` | ATS-301 门禁（WBS helper / ADR 引用 / 端口审计） | `RESULT: OK` |
| `06-wbs-update.log` | WBS 更新与**幂等**（第二次运行行不变） | `IDEMPOTENT` |
| `07-doc-consistency.log` | 文档所引数字与已提交日志的**照合** | `RESULT: OK` |

## 2. 负向对照守着什么

`04-node-test-negative-control.log` 是**证明检查会红**的那一步。检查不红
的检查什么都证明不了。

它把检测器**变异**，然后断言变异后的行为正是它该有的样子——而**未变异**
的检测器必须拒绝同样的输入。8 种变异：

| 变异 | 破坏的是什么 | 被抓住的断言 |
|---|---|---|
| M1 | 白名单不被执行 | 不在名单上的 API 被报成受控 |
| M2 | 静态参数规则被丢掉 | 运行期算出来的参数被报成受控 |
| M3 | 运行期值被说成静态 | 断言的 actual 被报成可改写 |
| M4 | 循环的拒绝被丢掉 | 跑 N 次的步骤被画成一个方块 |
| M5 | 字符串/注释不被跳过 | 不是调用的东西被报成调用 |
| M6 | 文件判定被反转 | 不能改写的文件被报成 writable |
| M7 | 理由码丢失 | 拒绝说不出为什么 |
| M8 | **对照**：未变异的检测器必须拒绝以上全部 | 反向控制 |

M8 是**对照**：没有它，上面的变异只能证明「这个模块可以被弄坏」，证明
不了「这个模块的检查是有效的」。

## 3. 文档的实测数字如何不可过期

`07-doc-consistency.log` 是**把文档钉在日志上**的那一步。

- 设计书 §7 与本 README 引用的数字，与 `03-probe-ast-subset.log` 里的
  数字**逐条照合**；
- 单元/集成/负向对照的用例数，与三份 suite 日志里的 `ℹ tests N` 照合；
- 本 README 的日志表，与**实际提交的日志文件**照合（README 不得提到一份
  不存在的日志，也不得漏掉一份已提交的日志）；
- 工作簿备注模板（`tools/update_wbs_ats314.py` 的 `NOTE_TEMPLATE`）里的
  数字，同样从 probe 日志派生——单元格因此不可能与日志分叉。

一个手抄进散文的数字是会与它描述的东西分叉的；一个**从日志派生**的数字
不会。

## 4. 已知边界（证据能证明什么，不能证明什么）

| 已实测 | **未**实测 / **未**实现 |
|---|---|
| 白名单的封闭性与每条规则 | **不是 TypeScript AST**：无类型解析、无作用域分析（Node Bridge 无第三方依赖，见设计书 §2） |
| 静态参数规则（含简写/展开/插值） | **不写回**：diff→语法检查→人工批准→原子写属 ATS-315 |
| 只读理由码的封闭集合 | **没有 UI**（ATS-315 / ATS-310 的范围） |
| 循环与本地函数里的步骤被拒绝 | 白名单不含 `page.setContent` / `page.click` 等其余 API（加进名单是设计决定） |
| 文件三态与 `writable` 布尔位 | **WDIO 脚本全被拒绝**——这是正确行为，不是缺陷 |
| 用例声明与 `test.step` 分开处理 | `test.step` 的回调体**不被展平** |
| 实 Bridge 上的 HTTP 面（10 例 IT） | 未在真实浏览器上跑过（本票不执行测试） |
| 检测器**不改一个字节**（IT 前后全树摘要相同） | |
